# Smart Cam — бинарный протокол (TCP)

Версия протокола: **1**. Транспорт: **TCP** (IPv4). Порядок байт: **big-endian** для многобайтовых полей.

## QR-код на ПК (удобство, не часть TCP)

Десктоп кодирует в QR одну строку **JSON** (UTF-8), схема **v1**:

`{"v":1,"h":"<host>","p":<port>,"t":"<token>"}`

- `h` — адрес, который телефон должен использовать в TCP-клиенте (при bind `0.0.0.0` на ПК подставляется типичный LAN-IP).
- `p` — порт сервера (число).
- `t` — тот же токен, что и в HELLO.

Мобильное приложение парсит JSON и заполняет поля подключения.

## Общая рамка сообщения

Каждое сообщение от клиента или сервера:

| Поле   | Размер | Описание |
|--------|--------|----------|
| magic  | 4      | ASCII `SCWB` (`0x53 0x43 0x57 0x42`) |
| ver    | 1      | Версия протокола, сейчас `1` |
| type   | 1      | Тип сообщения (см. ниже) |
| length | 4      | Длина тела `body` в байтах (uint32 BE) |
| body   | length | Полезная нагрузка |

Если `magic` или `ver` неверны, сервер закрывает соединение без ответа (или шлёт `ERROR` по возможности).

## Типы сообщений

| Код | Имя        | Направление | Описание |
|-----|------------|-------------|----------|
| 1   | `HELLO`    | клиент → сервер | Первое сообщение после подключения |
| 2   | `HELLO_OK` | сервер → клиент | Токен принят, параметры сессии |
| 3   | `FRAME`    | клиент → сервер | Один кадр JPEG |
| 4   | `SERVER_SESSION` | сервер → клиент | Кнопка Start/Stop на ПК (трансляция вкл/выкл) |
| 5   | `CLIENT_SESSION` | клиент → сервер | Кнопка Старт/Стоп на телефоне |
| 255 | `ERROR`    | сервер → клиент | Ошибка, после чего сервер может закрыть сокет |

## HELLO (type = 1)

**body (расширенный формат, мобильное приложение Smart Cam):**  
`UTF-8(token) || 0x00 || quality_u8`, где `quality_u8` — желаемое качество потока с телефона: `0` = low, `1` = medium, `2` = high.

**body (совместимость):** только UTF-8 токен без `NUL`. В этом случае сервер считает, что клиент запросил максимум (`quality = 2`).

Сервер сравнивает **только** часть токена (до первого `0x00`) с настроенным секретом.

- При успехе: один ответ `HELLO_OK` с телом качества (см. ниже).
- При неверном токене: ответ `ERROR` с кодом `AUTH_FAILED`, затем закрытие.

## HELLO_OK (type = 2)

**body:** два байта: `quality_u8` (как выше), затем `session_live_u8` — `1`, если на ПК активен режим трансляции (виртуальная камера / Start), иначе `0`.

Качество в `HELLO_OK` совпадает с `quality_u8` из `HELLO` (после clamp 0..2). Клиент кодирует JPEG и FPS по этому значению.

**Совместимость:** тело длины `0` — как medium и `session_live = 0`; длины `1` — только качество, `session_live = 0`.

## SERVER_SESSION (type = 4)

**body:** один байт: `1` — на ПК нажали Start (трансляция вкл), `0` — на ПК нажали Stop.

Сервер может послать в любой момент при активном соединении после `HELLO_OK`. Клиент синхронизирует своё состояние «идёт поток / нет».

## CLIENT_SESSION (type = 5)

**body:** один байт: `1` — на телефоне начали стрим, `0` — остановили.

ПК синхронизирует виртуальную камеру (Start/Stop) с телефоном.

## FRAME (type = 3)

**body:**

| Поле       | Размер | Описание |
|------------|--------|----------|
| width      | 4      | uint32 BE, ширина кадра (логическая) |
| height     | 4      | uint32 BE, высота кадра |
| jpeg_len   | 4      | uint32 BE, длина JPEG |
| jpeg_bytes | jpeg_len | Сжатый JPEG |

Сервер декодирует JPEG в RGB и подаёт в виртуальную камеру. Клиент может слать кадры только после получения `HELLO_OK`.

## ERROR (type = 255)

**body:**

| Поле        | Размер | Описание |
|-------------|--------|----------|
| code        | 2      | uint16 BE, код ошибки |
| message_len | 2      | uint16 BE, длина UTF-8 сообщения |
| message     | variable | Текст для логов/отладки |

### Коды ошибок (uint16)

| Код | Имя | Описание |
|-----|-----|----------|
| 1   | `AUTH_FAILED` | Неверный токен в HELLO |
| 2   | `BAD_MESSAGE` | Некорректный формат после HELLO |
| 3   | `SERVER_ERROR` | Внутренняя ошибка сервера |

## Поведение клиента

1. Подключиться к `host:port`.
2. Отправить ровно одно сообщение `HELLO` с токеном.
3. Дождаться `HELLO_OK`; при `ERROR` — показать пользователю и отключиться.
4. Циклически отправлять `FRAME` с JPEG.

## Поведение сервера

1. Принять соединение; первое сообщение должно быть валидным `HELLO` с корректным токеном.
2. Ответить `HELLO_OK` или `ERROR` + закрыть.
3. Читать последовательность `FRAME`; при нарушении формата — `ERROR` (`BAD_MESSAGE`) и закрытие.

## Пример размеров

Минимальный заголовок пакета: 10 байт (`magic` + `ver` + `type` + `length`).
